# Shopify 页面开发与体验验证

先查 [LLM Wiki](../../.wiki/_index.md) 和已有相关记录。将下面的执行结果存入 [Wiki 执行目录](../../.wiki/output/_index.md)，新结论回写 [页面验证结论](../../wiki/topics/page-validation.md)。

收到具体页面任务时，推进到用户授权范围内的最远阶段。每次交付保留同一份记录，从需求跟到上线效果。店铺权限、收费、正式发布仅在实际需要时一次说明。

## 1. 定义改动和成功标准

记录页面 URL、模板、美国市场、主要设备、目标人群、当前主题 ID、可回退版本。用一句话写出“谁遇到什么问题，这次改动预期如何改善”。记录主要指标的分子、分母、来源和基线日期，同时记录促销、流量来源及库存。例如定制窗帘详情页的主指标可用“访问该页的会话中成功加入成品购物车的比例”；护栏为错误报价、样品误选、结账完成和移动端性能。门槛与观察窗口按本次历史流量设定。

## 2. 在现有主题上开发

1. 确认 Liquid 主题或 headless、代码位置、发布流程、实际模板与已有应用区块。记录会随主题切换的代码和独立于主题的菜单、商品、元字段、应用或后台设置。共享数据的变更单列预览与恢复方案。
2. 优先复用现有 section、block、snippet 和主题设置。仅改目标页面时使用独立模板或可配置开关，检查同模板的其他商品。保持已有 SKU、行属性和分析事件语义兼容。
3. Shopify AI Toolkit 可用时，先查当前 Liquid 对象、schema 或目标 API，再用其验证工具检查变更，保存提示、修复和复验结果。采用官方 Dev MCP 接入时，先列出可用工具，读取 Liquid 指引，再按实际工具 schema 使用；以实际调用回执为准。 [Shopify AI Toolkit](https://shopify.dev/docs/api/ai-toolkit)
4. 在主题源码根目录运行检查。以下命令中的 STORE、BASE_ID 由实际店铺与基线替换。已有主题仓库时使用其分支和依赖。仅在需要拉取基线时指定新的空目录，保护现有工作。

```sh
shopify theme list --store "$STORE"
shopify theme pull --store "$STORE" --theme "$BASE_ID" --path "$EMPTY_DIR"
# 从开发工作目录运行
shopify theme check
shopify theme dev --store "$STORE"
```

记录 Theme Check 新增错误并修复，对既有告警单列说明。在开发预览打开真实商品 URL，记录可点击的预览入口、页面路径、主题 ID、测试设备与时间。需要持久草稿给团队或 SimGym 使用时，先核对主题库，首次用 `shopify theme share --store "$STORE"` 创建未发布主题，后续定向更新同一草稿。结账扩展另用支持的 Shopify 托管测试入口验收。 [Theme CLI](https://shopify.dev/docs/api/shopify-cli/theme) · [开发主题预览](https://shopify.dev/docs/api/shopify-cli/theme/theme-dev)

## 3. 在浏览器走一遍买家流程

范围按改动选择。记录每条用例的预期、实测、设备、证据及问题负责人。对价格、支付或订单链路有影响时，验收到测试订单明细。

| 用例 | 如何操作 | 通过标准 |
| --- | --- | --- |
| 导航与发现 | 从美国移动端首页、集合、搜索或广告落地页进入目标 SKU，再返回 | 链接、筛选、返回状态及市场正确，关键按钮可见可点 |
| 定制与报价 | 输入合法英寸分数、最小/最大值、越界值；同 SKU 配两扇尺寸不同的窗；修改其中一行 | 合法输入按价表计价，非法输入给出就地提示；购物车和订单保留每扇窗的尺寸、单价、数量 |
| 样品和成品 | 分别加样品、成品、混合购物车；覆盖普通和已启用的加速购买入口 | 商品类型、付款金额、运送方式及工单与选择一致 |
| 可访问性与性能 | 手机/桌面、键盘、焦点、字段标签、错误提示；对相同页面设备网络条件比较 Lighthouse | 主要操作可完成。记录前后 LCP、CLS、可用的交互指标和图像/脚本变化；上线后查看实际访客数据 |
| 事件与结账 | 检查浏览、加购、发起结账、购买事件；在适当测试环境检查成功交易及失败重试 | 事件的商品 ID、订单 ID、金额、币种和去重正确；订单数据及通知符合预期 |
| 回归 | 覆盖另一款共享模板商品、缺货状态、刷新购物车和返回修改 | 既有商品、购物车和旧配置仍可用 |

使用测试店或已准备的测试支付环境。若需在营业店启用支付测试模式，单独确认影响与窗口。 [测试订单](https://help.shopify.com/en/manual/checkout-settings/test-orders) · [主题性能](https://shopify.dev/docs/storefronts/themes/best-practices/performance)

## 4. 用 SimGym 验证体验并复测

**资格**。核对 Liquid 店面、有效套餐、已启用 Shopify Network Intelligence、非永久密码页，且至少一件正价非礼品卡已发布到 Online Store。普通 private mode 可支持。主题对比至少需要一份草稿。Headless 项目采用同任务的真人或浏览器可用性测试，再用线上数据验证。 [SimGym 官方手册](https://help.shopify.com/en/manual/online-store/simgym)

1. 后台进入 Apps → SimGym，按问题选择测试。首页或集合改版用 Product discovery，详情页文案、规格或加购疑虑用 Add-to-cart confidence，跨页面诊断用 Entire shopping journey。需要同一批模拟买家比较两个版本时选 Theme comparison，把目标草稿放在 Theme 2。
2. 确认主题 ID、草稿版本、目标页面经过的入口，以及两个主题共享的商品、菜单、价格和折扣。一次聚焦一个假设。核对当月剩余额度和界面报价，涉及额外付费时说明金额再请求授权。
3. 点击 Run simulation，等待完成。打开建议下的 View findings，查看买家实际走过的页面、停顿、退出点与回放。记录哪些模拟买家确实触达目标页；如果样本没有触达、被机器人限制拦截或受共享数据干扰，标记验证不足。
4. 把能复现的问题转成修改项。例如模拟买家在输入宽度时退出，先在移动端复现，再调整单位提示、非法值反馈或操作顺序。重新跑受影响功能用例，并在相同条件下复测。对比结果记录为改善、持平、恶化或证据不足。
5. 交付时保留模拟名称、时间、主题及版本、测试焦点、发现、回放定位、修复记录与复测结论。模拟加购用于判断体验；成交及增量收益用真实订单和上线后的对照分析确认。

## 5. 发布、回滚和复盘

- 发布前核对最新线上主题和候选草稿的差异，补入开发期间其他人已上线的更改。交付预览、验收结果、未决项、旧主题 ID 和变更清单。按当次授权发布指定版本。
- 上线后立即用美国买家路径复查链接、价格、加购和结账，核对事件与订单。出现错误报价、丢失尺寸或无法结账等关键问题时，按约定回滚到已核实的上一个主题版本；逐项恢复相关共享设置，重测同一流程。
- 按最初约定比较实际加购率、结账完成率、成品成交和移动端表现。优先使用可用的同期对照；前后对比时对齐广告来源、设备、促销和星期，并记录样本量。考虑定制品购买延迟，在成熟窗口回看样品到成品订单及退款。样本不足时定为待观察。
- 将结论写回记录：保留、迭代或回退，附证据、负责人、复查日期。失败或证据不足的用例返回对应开发或验证步骤。 [实际访客性能](https://help.shopify.com/en/manual/online-store/web-performance)
